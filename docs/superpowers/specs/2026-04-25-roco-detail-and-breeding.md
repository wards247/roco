# 洛克王国生蛋系统详情页与生蛋推荐实现

## 详情页

当前路由包含精灵详情页：

- `/pokemon/:baseId`

从精灵库和我的精灵页面点击卡片都可以进入详情页。

详情页展示：

- 精灵头像和身体图
- 精灵名称、页面名、类型、分类、孵化状态
- 种族值
- 图鉴介绍
- 进化路线
- 所属蛋组
- 生蛋候选数量
- 生蛋候选列表

详情页优先读取本地 rocom 详情 JSON：

- `/rocom/data/pets/{id}.json`

如果该详情存在，则使用：

- `name` 拼接 friends 详情图
- `evolution_tree` 展示完整进化路线
- `world_profile` 展示图鉴信息
- `base_hp/base_phy_atk/base_mag_atk/base_phy_def/base_mag_def/base_spd` 展示种族值
- `breeding_profile.egg_groups` 补充蛋组

当详情页打开的是完整精灵库里的非最终形态，例如 `3001 喵喵`，本地蛋组库可能没有该 `base_id`。此时生蛋候选使用 rocom 详情里的 `breeding_profile.egg_groups` 作为蛋组标记位，并排除同一进化树上的精灵。

rocom 数据中存在同名同资源但种族值为 0 的占位/旧编号记录，例如 `4005 圣水守护`、`4074 霜翼领主`。完整精灵库和详情页进化路线会隐藏这类 0 种族值记录，优先保留同名同资源且种族值非 0 的记录。

进化路线按阶段横向排列；同一阶段存在多种形态时，在该阶段列内纵向排列。

## 本地候选规则

详情页的候选列表已经完全本地化，不再依赖远程 `hatch-pet` 接口。

候选规则是：

- 找到当前精灵所属的所有蛋组
- 遍历本地全部可生蛋精灵
- 只要共享任意一个蛋组，就视为候选
- 多蛋组精灵可以跨蛋组兼容
- 同一进化链只保留一条代表记录，按 `family_key` 去重

候选条目副标题展示：

- 完整 `family_chain`
- 共享的蛋组名称

## 生蛋推荐

生蛋推荐页面从我的精灵中读取数据，并先用本地精灵库补全：

- `egg_group_ids`
- `can_hatch`

然后按性别拆成两个兼容性卡片：

- 雌性兼容
- 雄性兼容

推荐结果会排除不可生蛋的精灵，只保留 `can_hatch !== false` 的记录。

## 系统高兼容排行

生蛋推荐页右侧展示系统总的高兼容排行，用于帮助决定优先捕捉哪些精灵。该排行不依赖“我的精灵”，而是基于本地全部可生蛋精灵计算。

排行规则：

- 只统计 `hatch_status_text = 可生蛋` 的精灵
- 同一进化链按 `family_key` 去重
- 多蛋组精灵按完整蛋组集合参与计算
- 任意共享一个蛋组即视为兼容
- 按可兼容的不同族链数量降序排列

排行只展示简略信息：

- 名字
- 所属蛋组
- 兼容数

鼠标悬浮排行条目时显示兼容详情浮层，列出前 10 个兼容候选，超出部分显示剩余数量。点击排行条目可进入对应精灵详情页。

## 兼容性计算

兼容性判断基于蛋组集合交集，而不是单个蛋组 ID。也就是说，只要两只精灵的蛋组集合有交集，就判定为可兼容。

这使得多蛋组精灵可以自然参与跨蛋组配对，例如同时属于多个蛋组的精灵会自动兼容所有共享蛋组的候选。

## 跳转

详情页中的候选项、兼容性卡片中的条目都支持点击跳转到对应精灵详情页。
